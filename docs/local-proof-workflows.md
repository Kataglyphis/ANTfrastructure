# Preserved local operational workflows

Recurring host and local proof drivers are versioned in `linux/scripts/local-proof/` and
`linux/host-config/`. Extend the canonical script before its next use. Keep invocation JSON,
source snapshots, extracted probe inputs, output, receipts and superseded script bytes under
ignored `logs/`; those directories are evidence, never the sole home of recurring functionality.

The checked-in [inventory](../linux/scripts/local-proof/inventory.json) maps the session's old
toolkit to canonical files and records the original SHA256. Superseded versions, exact patch
recipes and historical checkpoint writers stay with their evidence. New checkpoints use the
shared driver below. The inventory does not authenticate a receipt or enumerate every file
generated by a build.

launchers. A new platform or source-proof kind needs a reviewed profile and matching tests.
The targeted source scope `operational-tools` permits only the same exact patch, cleanup and normal-hook proof as the existing named source profiles. It grants no compiler or image acceptance.
The retained `probe-soname-load.py` worker takes the soname, expected prefix and maps output as positional arguments; its original bytes remain bound by the supplied qualification.
The independent cross-Clang image probe requires `--sysroot=/` for all six wrappers, matching Debian's absolute target linker scripts. Its separately constructed positive fixture uses that root; four negative controls reject the old `/usr/<triplet>` root for both foreign C/C++ drivers. A corrected host probe can check an already built immutable image; record its actual input hashes in a fresh invocation and retain the failed old probe. This does not replace the baked smoke or grant SDK, complete C++ ABI or GPU acceptance.
Default paths derive from `Path.home()`; original qualifications, loader probes, parallel-source
producers, compiler unit identities and cleanup authorization files are explicit inputs.

## Native GPU-to-Media handoff

Use `gpu-oci-handoff.py launch|seal --compiler-plan PLAN --gpu-invocation GPU_INVOCATION
--context FRESH_PARENT/gpu-context-NAME --unit webgpu-normal-gpu-export-amd64-DATE-N.service`.
The explicit reviewed profile supports ordinary ROCm amd64 only. It requires the original
qualified SDK and compiler ancestry, complete exact source proof, unchanged invocation hashes
and the GPU producer's actual successful terminal state. Launch binds the current engine's
manifest/config and independently resolves the bare immutable local manifest ID to the same
config and manifest. The host export uses that verified ID through the shared bounded
transport. A local Docker-loaded image can lack a repository@digest name even when
inspection reports that RepoDigest; its inspected config ID is a different identity.
Media's FROM still uses repository@digest with the verified native OCI context.
The unchanged byte reserve applies before starting; existing units, contexts and receipts refuse.

Sealing rehashes the complete native OCI layout, verifies all SDK descriptors/diffIDs and
immutable shared parent layer identities, and requires both actual export pipeline statuses.
Only after a successful stop and independent terminal-state observation is a stopped receipt
written. Preserve partial output on failure. Local cross builds do not emit the pushed
image's ancestry annotation; this profile checks real native ancestry instead of inventing
Config labels or modifying an image manifest. Supplied receipts do not authenticate provenance.

Then use `launch-normal-media.py --compiler-plan PLAN --gpu-invocation GPU_INVOCATION
--parent-proof GPU_OCI_STOPPED_PROOF --output FRESH_OUTPUT --unit
webgpu-normal-media-amd64-DATE-N.service --image-repo ant-local/webgpu-NAME`.
It revalidates that exact subject and starts the unchanged ordinary `build-cross-stage.sh`
with native GPU context and digest pin, `ORT_WEB_REQUIRED=1` and
`ORT_WASM_WEBGPU_FLAVORS=true`. Both actual Wasm build/probe receipts remain required;
forwarded flags alone prove neither flavor. Shared host admission retains idle-engine,
collision, ambient-flag, fresh temporary-root and mandatory disk checks.

Carry the existing `normal_stage_launch.py`, `gpu_source_profile.py`, native OCI/seed and
proof helpers beside these entries. `test-gpu-handoff.sh` uses real synthetic OCI bytes and
hardlinks with explicit engine/unit doubles; the standard native seed and stage suites
retain their earlier compiler/SDK scopes. They do not establish actual image completion,
full binary licences, native loader ABI, GPU parity or digest-specific FINAL acceptance.

## Live configure snapshots

Use `snapshot-live-configure.py` beside its `capture-live-sccache-log.py`, `cache_capture_profile.py`, `native_oci_layout.py`, `native_oci_seed.py` and `proof_commands.py` companions. This replaces repeated copying/hash commands before the normal MIGraphX RUN removes its private build directory. The current process must match the normal build marker and remain the same start identity throughout copying; its supplied producer unit must be live. The output parent is a plain directory and the new output cannot overlap the source.

```bash
python3 linux/scripts/local-proof/snapshot-live-configure.py \
  --invocation /absolute/path/to/gpu-run/invocation.json --pid 12345 \
  --relative-root tmp/migraphx-source-stack/backend/build \
  --output /absolute/path/to/fresh-configure-snapshot
```

It copies only CMakeCache.txt, build.ninja, CMakeFiles/rules.ninja and CMakeFiles/CMakeConfigureLog.yaml, each at most 32 MiB and together at most 64 MiB. Every source/copy hash must match, source directories/files cannot be symlinks, and existing outputs remain preserved. A failed copy leaves diagnostic partial files without a passed observation. The invocation and process marker do not authenticate producer ownership; a stable snapshot proves neither a completed phase, final cache-error attribution, binary linkage/licence closure nor image acceptance. `test-live-configure-snapshot.sh` uses real file copies and explicit unit/process doubles.

## Live cache log retention

`replay-sccache-log-capture.py` reuses the bounded read-only unit transport with the current canonical `capture-live-sccache-log.py` and its `cache_capture_profile.py` companion. Both reader inputs are hashed in the invocation. The existing GCC, LLVM, Rust and Python phases retain their compiler unit names; `--phase migraphx` matches the actual normal `bash /opt/scripts/03-media/build/migraphx/build-image.sh` process and uses `webgpu-gpu<run>-migraphx-error-capture-<date>-<attempt>.service`.

Supply the actual live PID, producer unit, original reviewed transport template and a fresh output. The reader opens only the existing regular `/proc/<pid>/root/tmp/sccache.log`, tracks process start identity and refuses replacement of that live log inode. It retains all bytes before closing the descriptor, including after the RUN filesystem disappears. Each replay writes its unit log beside the new invocation. `seal-sccache-log-capture.py` verifies worker/companion hashes, raw terminal status, file size/SHA and stopped/PID0 state. A reader timeout is explicitly partial, and neither an empty file nor a completed reader classifies compiler-cache errors or accepts an image. `test-live-cache-capture.sh` uses synthetic process files and command doubles; it does not prove a genuine build or source provenance.

`audit-failed-source-check.py` also retains a completed mutation run containing `SURVIVED` failures before preflight starts. Its failed receipt requires exact passed/survived IDs, the matching failure summary, actual failed/PID0 unit, cleanup and independent absence. Quality-only failures retain their strict complete mutation proof. Interrupted or other incomplete mutation failures need separate inspection; a failure audit never accepts source.

## Local BuildKit cache transfer

Use `seed-buildkit-cache.py` for recurring local cache seeding rather than regenerating `cp` commands. Keep its `buildcache_transfer.py`, `native_oci_layout.py`, `native_oci_seed.py`, `proof_commands.py` and type companion together. Supply a producer receipt with its actual successful loaded terminal and stopped state; the current user unit must also be inactive with PID zero. The caller is responsible for selecting the correct producer and ensuring exclusive access to both cache trees. These checks do not authenticate that relationship or prevent a separate uncooperative writer.

```bash
python3 linux/scripts/local-proof/seed-buildkit-cache.py \
  --source /absolute/path/to/stopped-export \
  --destination /absolute/path/to/fresh-cache-root/actual-stage-slug \
  --producer-proof /absolute/path/to/producer/proof-stopped.json \
  --receipt /absolute/path/to/fresh-cache-transfer.json
python3 linux/scripts/local-proof/seed-buildkit-cache.py \
  --verify-only --receipt /absolute/path/to/fresh-cache-transfer.json \
  --dry-run-log /absolute/path/to/normal-driver-dry-run.log \
  --image-tag ant-local/example:cross-compiler-amd64
```

Only the modern OCI image-manifest BuildKit cache format is supported. Every referenced manifest, cache config and layer is size/hash checked; repeated descriptors are counted once. Only immutable content-addressed blobs are hard-linked. Index and layout bytes get separate files so the next export cannot overwrite the old mutable metadata. Cache roots must be plain disjoint directories on one filesystem, with a fresh destination and receipt outside both trees. Existing outputs are preserved. A failure leaves partial diagnostic files without a passed receipt. Reverification checks source and destination bytes, shared blob inodes, independent metadata, producer identity and exact accounting.

Select the destination from the ordinary driver's own stage-cache path; do not invent another slug algorithm. Before the next build, explicitly set its `BUILDKIT_CACHE_DIR` to the destination's parent and retain a normal `--dry-run` showing `--cache-from type=local,src=<destination>`. Verify that log with the paired `--dry-run-log` and `--image-tag` options above: require exactly one normal build, the intended image, caching enabled and exactly the transferred local import. This checks supplied log bytes, not the provenance or execution of that command. A fresh output directory or unchanged GNU source closure does not carry over an older namespace. The transfer helper does not rewrite plans or relax source, full-preflight, base ancestry, disk-reserve or publication gates. Never seed or modify a live export, and never restart a producer merely to chase hits. Actual solve logs and compiler counters remain the cache evidence. `test-buildcache-transfer.sh` uses real synthetic files and an explicit systemd double; it proves no actual solve, source authenticity or image acceptance.
