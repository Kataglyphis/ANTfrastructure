# Preserved local operational workflows

Recurring host and local proof drivers are versioned in `linux/scripts/local-proof/` and
`linux/host-config/`. Extend the canonical script before its next use. Keep invocation JSON,
source snapshots, extracted probe inputs, output, receipts and superseded script bytes under
ignored `logs/`; those directories are evidence, never the sole home of recurring functionality.

The checked-in [inventory](../linux/scripts/local-proof/inventory.json) maps the session's old
toolkit to canonical files and records the original SHA256. Superseded versions, exact patch
recipes and historical checkpoint writers stay with their evidence. New checkpoints use the
shared driver below. The inventory does not authenticate a receipt or enumerate every file
generated by a build.

## Closed direct-wrapper preflight receipts

For an already closed direct owned-wrapper run, use `python3 linux/scripts/local-proof/complete-direct-preflight.py --directory RUN --reference PRIOR_COMPLETE_PROOF`. It reads the original invocation, strict stopped mutation seal, raw command/cache statuses, exact log slice and independent committed source snapshot. Every canonical group and discovered suite must appear once; discovery retains the unchanged canonical runner's literal library exclusions and regular-file requirement, including its non-runnable harness; the original cleanup identity, readonly source mount, empty filters and final report permissions must match. Fresh successful full-CID and ownership-label queries precede an exclusive receipt write. Failed queries retain diagnostics and refuse acceptance. This does not rerun sealing or cleanup, create a driver `run.json`, authenticate evidence, or prove images, packages or hardware. Preserve the complete helper tree beside this entry.

## Operational memory appends

Run `python3 linux/scripts/append-operational-memory.py --memory FILE --expected-bytes N --expected-sha256 SHA256 --append-file NOTES --directory NEW_PROOF_DIR` on the Linux host. Inputs must be single-link regular files; notes must be nonempty UTF-8. The destination proof directory must be new and its parent trusted and present. Copy both `operational_memory` modules, `host_commands.py` and `source_ci/common.py` beside the entry in their original layout.

The helper requires a successful user-systemd JSON query, validates each matching controller's identity and both PIDs, and scans readable process arguments for storage-guard and safe-prune names, including underscore spellings and ancestor processes. Missing, unreadable or unknown observations refuse the append. Terminal failed, inactive or exited services with both PIDs zero are allowed; process checks still apply. This is an observation of names and arguments, not authentication or a promise that another writer will remain idle.

Under a nonblocking file lock, it verifies the exact expected prefix, preserves exclusive byte-for-byte prefix and append snapshots, then rechecks prefix and inode before writing with `O_APPEND`. It verifies the entire resulting file, rechecks both saved snapshots and writes a passed receipt only after successful synchronization. Snapshot bytes are checked before writing too; a failed post-write check preserves the already extended memory and cannot produce a passed receipt. Short writes are completed; no failure path truncates memory or overwrites old evidence. Existing directories refuse. If a write or final receipt fails after an append, inspect the retained bytes before continuing: repeating the old expected prefix must fail. Other writers can ignore locks, rename or truncate files, and the file/proof updates are not one crash-atomic transaction. Fixtures and mutations prove these boundaries with synthetic services and files, not live-host controller absence or protection from hostile writers.

## Working consumer sources

The optional working-source command requires every tracked regular-file edit to be staged. It copies the selected committed base into an independent Git store, applies a binary patch from the source index, and verifies the complete index and actual file bytes, permissions and literal links. The original owner HEAD and selected base are recorded separately; neither is substituted for the staged overlay.

Committed, recursive and working copies retain every locally configured origin URL,
in its original order and with literal value boundaries. This keeps workflow repository
selection from seeing a local directory name such as `editor`. Copying uses local objects;
no remote is contacted. A source without a configured origin keeps the clone's local
reference. Existing copies are not silently rewritten on reuse; inspect their metadata
or prepare a fresh copy. Origin metadata does not authenticate the source or establish
workflow acceptance.

When permanent materialized copies consume the source reserve, keep a durable archive
and restore temporary independent checkouts with `restore-consumer-archive.py`.
Its schema-1 `archive.json` records the base, HTTPS GitHub origin, whether the original
is shallow, and SHA256 values for `base.bundle`, `working.patch`, `working-index.bin`
and `versioned-files.json`. Shallow originals also carry `original-shallow.bin`.
Create the bundle from the selected base, the binary patch and index from the staged
source, and file metadata through `preserve-consumer-sources.py:working_files`.
These native Git operations and the existing preservation APIs do not create a consumer commit.

Pass the expected manifest digest from the reviewed source plan:

```bash
python3 linux/scripts/restore-consumer-archive.py \
  --archive /durable/source-archive --expected-manifest-sha256 "$ARCHIVE_SHA256" \
  --destination /temporary/independent-checkout --receipt /evidence/source-restore.json
```

The helper checks every fixed archive input before allocation, restores only the exact
original shallow metadata before checkout, applies the staged patch and compares the
complete index and actual files, modes and literal links. Missing Git objects fail;
metadata paths and kinds must match the index before any file mode is restored.
Archive inputs are checked again before the receipt is written.
do not synthesize shallow boundaries to suppress that failure. A bundle verifier's
complete-history message alone does not prove the original has complete history.
Copy the helper with its preservation, host-command and `source_ci/common.py` companions.
The receipt covers the parent only; preserve and bind recursive dependencies separately.
Temporary materializations may disappear after reboot, so retain the complete durable
archive and restore it before reusing paths. Filesystem availability does not prove a
tmpfs user quota has room. The expected digest selects bytes; it does not authenticate
their producer, run a build or establish hardware acceptance.

A gitlink can have three different revisions: the selected base records A, the current index records B, and the actual child checkout contains C. The copy must retain B. Reading the working-tree diff would substitute C; ignoring submodules in the patch would omit B. The index-only patch avoids both errors. The unstaged regular-file guard may ignore submodule working-tree differences because actual child HEADs, indices and file trees require separate explicit bindings.

This mode does not initialize or recursively preserve child sources, authenticate a pin, or prove a build or inference. Preserve every used child independently and verify its binding before running a consumer. Existing committed-tree acceptance still requires exact recursive gitlink matches and clean sources. Temporary real Git controls exercise the staged/index/checkout distinction, refusal paths and source races; mutation controls cannot establish source authenticity or hardware acceptance.
