# Preserved local operational workflows

Recurring host and local proof drivers are versioned in `linux/scripts/local-proof/` and
`linux/host-config/`. Extend the canonical script before its next use. Keep invocation JSON,
source snapshots, extracted probe inputs, output, receipts and superseded script bytes under
ignored `logs/`; those directories are evidence, never the sole home of recurring functionality.

The checked-in [inventory](../linux/scripts/local-proof/inventory.json) maps the session's old
toolkit to canonical files and records the original SHA256. Superseded versions, exact patch
recipes and historical checkpoint writers stay with their evidence. New checkpoints use the
shared driver below. The inventory does not authenticate a receipt or enumerate every file
generated by a build.

`local-proof/` in this table means `linux/scripts/local-proof/`. Every launcher has explicit
inputs and `--help`. `capture-compiler-cache-log.py` is an image-side worker: its sole positional
argument is an existing output directory. Copy the required sibling scripts and C/C++ fixtures
together; the inventory lists the closure. The two `test-*.py` and two `mutate-*.py` drivers
preserve independent refusal fixtures and actual parse-valid guard mutations.

These compiler/SDK proof profiles retain their reviewed Linux amd64, three-backend, six-wrapper,
pin, base-ancestry and accepted-checkpoint contracts. They are not general arbitrary-image
launchers. A new platform or source-proof kind needs a reviewed profile and matching tests.
The targeted source scope `operational-tools` permits only the same exact patch, cleanup and normal-hook proof as the existing named source profiles. It grants no compiler or image acceptance.
The retained `probe-soname-load.py` worker takes the soname, expected prefix and maps output as positional arguments; its original bytes remain bound by the supplied qualification.
The independent cross-Clang image probe requires `--sysroot=/` for all six wrappers, matching Debian's absolute target linker scripts. Its separately constructed positive fixture uses that root; four negative controls reject the old `/usr/<triplet>` root for both foreign C/C++ drivers. Mutations restore each obsolete foreign root and must fail the fixture. A corrected host probe can check an already built immutable image; record its actual input hashes in a fresh invocation and retain the failed old probe. This does not replace the baked smoke or grant SDK, complete C++ ABI or GPU acceptance.
Default paths derive from `Path.home()`; original qualifications, loader probes, parallel-source
producers, compiler unit identities and cleanup authorization files are explicit inputs.

## Observe and checkpoint

```bash
python3 linux/scripts/local-proof/observe-full-preflight.py \
  --directory logs/test-results/preflight-001 \
  --output logs/test-results/preflight-001-observation-001.json --processes

python3 linux/scripts/local-proof/checkpoint-proof-runs.py \
  --preflight logs/test-results/preflight-001 \
  --preflight logs/test-results/preflight-002 \
  --state logs/test-results/work/state.json \
  --markdown logs/test-results/work/CURRENT.md \
  --output logs/test-results/work/units-001.json
```

Both runs use adjacent `<directory>-invocation.json` records. Checkpointing preserves unrelated
state fields and old handoff text, records every supplied unit, and replaces only its own marked
Markdown block on later calls. A running unit's `Result=success` is an observation, never a pass.
No observer stops or restarts a producer. The shared watcher recognizes a retained oneshot only after its recorded exit, zero main PID and `active/exited` state; a live success field still cannot finish observation. Sealing requires its loaded successful terminal state,
exact mutation IDs, all source groups, raw statuses, cleanup and an independent absence query.

The optional `replay-full-preflight.py --jobs 8 --memory 20g` profile additionally requires
`--resource-admission`, `--existing-preflight` and `--compiler-unit`. It rechecks the existing
four-worker/12-GiB producer's identity, memory peak, current limits and live host reserve before
creating the new run. It never changes that producer. Other resource profiles require review.

## Failed compiler linker diagnostics

`compiler-prefix-diagnostic.py prepare|launch|seal` takes an explicit failed-plan JSON,
directory, fresh unit and local image name containing `unverified`. Preparation requires a
loaded failed producer with zero PID, a nonzero exit and an absent normal candidate. It extracts
the unchanged Dockerfile prefix before the required smoke and labels that diagnostic image.
Launch retains the normal 180-GiB admission, original source identity, bounded unit and compiler
cache arguments. It can execute heavy stages again; a prefix extraction does not prove reuse.
Neither extraction nor a successful diagnostic build qualifies a compiler, SDK or final image.

After sealing that component, `launch-cross-clang-link-probe.py launch|seal` binds its exact
image to `--prefix-proof`, a fresh unit/directory and `--mode baseline|gcc-sysroot`. It copies the
worker, shell entry, minimal C fixture and existing native-wrapper C/C++ fixtures together.
The worker uses the image's baked bounded command transport and normal LLVM loader publication.
It preserves real verbose linker stderr, dynamic/static results, GNU-reported sysroots and
static native/QEMU executions for all three architectures and both drivers. The optional mode
changes only the foreign diagnostic commands' sysroot to GNU's reported root. The native
GNU driver is the unprefixed source binary and may legitimately report an empty sysroot; its
native wrapper remains unchanged in both modes. Raw GNU facts are written before validation. It is evidence for a
source repair, never a replacement for repairing and rebuilding the normal wrappers.

Sealing requires the exact six tuples, unchanged native Clang bytes, all three backends, no
preload and real successful required links/executions. Expected baseline foreign failures must
have positive raw statuses and actual stderr; a timeout or signal cannot supply them. Owned
containers are bounded, removed by the shared cleanup helper and independently queried absent.
Keep both failed and successful controls. The tests and mutations exercise refusal behavior
with doubles; only retained actual runs can prove what the image did.

The ordinary common compiler smoke now preserves linker stderr and its raw failure status in
the aggregate diagnostic. It refuses invalid temporary allocation and records failed cleanup.
Its C input through both drivers still does not prove the full C++ ABI or final runtime.
Object and link suites share the harness's invalid-allocation emitter; its failed, empty and
missing-directory outcomes remain distinct.

## SDK component qualification

Pass the actual normal SDK's `invocation.json` through `--sdk-invocation` to both
`compiler-image-qualification.py launch|seal` and `native-oci-handoff.py launch|seal`.
Keep `--plan` pointed at the unchanged compiler plan. The reviewed profile currently accepts
only an amd64 SDK from that same complete source and its sealed 26-layer compiler parent;
new architectures or parent layouts require their own reviewed profile and controls.

The qualifier uses a fresh `webgpu-sdk-image-qualification-<id>.service` and output directory.
Retain the original `--plain-load-probe` and `--original-qualification` inputs. The SDK's
materialized `/opt/llvm-target` must own all 157 native tools and source LLVM loader selection;
its `llvm-target-amd64` alias, exact two native wrapper scripts, driver byte comparisons and
actual native C/C++ object/link/execution smokes must pass in default and login shells.
The compiler profile still requires all three targets and four foreign static QEMU executions
per mode. The SDK profile neither substitutes a compiler proof nor claims foreign SDK, complete
C++ ABI, Vulkan API or GPU inference coverage. Native materialization replay on a disposable
compiler container remains a separate component check.

SDK OCI exports use `webgpu-normal-sdk-export-amd64-<id>.service` and a fresh `sdk-context-*`
directory beside the compiler plan. Sealing hashes every native blob, binds the actual SDK
manifest/config and matches every compiler parent descriptor and diffID; the compiler path
retains its original 12-layer base check. The unchanged 180-GiB admission applies before an
export or subsequent heavy build. Receipts record the supplied invocation, parent and source
proof hashes; they do not authenticate those inputs. SDK component success never supplies a
final runtime or consumer receipt.

Copy `proof_subject.py` and `proof_commands.py` beside both CLIs; the OCI handoff also requires
`native_oci_layout.py` and `native_oci_seed.py`. Their CPU worker uses
`probe-cross-clang-image.py`, `qualify-compiler-with-cross.sh`, the original native qualifier,
loader probe and C/C++ inputs together. SDK fixture runs also carry `sdk_profile_fixture.py`;
all recurring logic stays versioned and per-run arguments/results stay under `logs/`.

## Verified parent layer reuse

SDK exports use the current versioned toolkit's `01-core/context-management.sh` and pass the
sealed compiler parent proof as the fourth `export_image_to_oci_layout` argument. The default
three-argument path retains its existing reset policy. The optional seeded path refuses any
existing destination, then checks the parent receipt, index, manifest, config and every blob's
size/SHA256 before linking unique layer files into the fresh child context. Unsupported
hardlinks fail; no silent full-copy fallback changes the space requirement. Parent and child
contexts must not overlap or resolve through symlink directories, and proof/metadata/layer
inputs remain regular files. Child index, layout and config are written independently.

`tar --skip-old-files` preserves those immutable layer links. The transport retains producer
and extractor raw statuses, including under conditional callers and ordinary errexit, and
returns the rightmost pipeline failure. Seeded exports write `<context>.transport.json` and
`<context>.parent-links.json`. The sealer requires both statuses to be zero, the exact worker
hash manifest, every recorded unique digest/path, source/child device/inode and post-link
mode/owner/mtime/ctime identity, and independent child index/layout files. Creating the links
itself changes link metadata; no other writer/linker may change it before that export is sealed.
Source file hashes and logical output paths remain unchanged.

Only layers are shared. Parent receipt and source paths remain explicit, and every final child
blob and ancestor descriptor/diffID is still verified. These local checks do not authenticate a
supplied parent receipt or establish complete ABI/GPU acceptance. The original 180-GiB admission
still applies; shared-byte arithmetic is not a disk guard. Re-measure actual space and preserve
the usual cachemount, image, source and receipt protections during any authorized cleanup.

`test-native-oci-seed.sh` uses synthetic OCI data, real tar extraction and declared engine/unit
doubles to test preservation, symlink/path/receipt refusals, equal-byte inode changes, both raw
failures and the actual SDK launcher/sealer logic. Mutation recipes break these guards. Copy its
`native_oci_seed_tests.py` and `native_oci_transport_fixture.py` companions together. The shared
layout module retains the existing compiler API and 12-layer base checks.

## Authorized cleanup

```bash
python3 linux/host-config/autonomous-safe-prune.py launch \
  --directory logs/host-maintenance/prune-001 \
  --unit webgpu-safe-prune-001.service \
  --authorization /absolute/path/to/owner-operational-rules.md
```

The supplied file must contain the standing owner authorization for autonomous canonical
`prune-safe.sh` cleanup. The worker retains that check, snapshots image identities and all
cachemount IDs, and skips reclaim when the unchanged 180-GiB reserve already passes. It uses
`PRUNE_KEEP_GB=120`, disables duplicate-cachemount cleanup, and retains at least 100 GB during
builds. A smaller explicit `--keep-gb` requires `--idle-store` and an idle store before and after.
Changed identities, failed queries or failed cleanup cannot produce a successful receipt.
Call the same driver with `seal` after its loaded successful terminal state; retain the original
directory, unit and authorization arguments. This creates no timer or recurring service.

These checks record supplied facts; they do not authenticate an authorization file, prove GPU
inference or replace final runtime/consumer acceptance. See [host setup](linux-host-setup.md#b7-reclaiming-disk-without-losing-the-compile-caches)
and [quality tooling](code-quality-tooling.md#preserved-local-proof-workflows).

## Validation

`bash linux/scripts/tests/test-local-proof-tools.sh` checks the inventory, portable paths,
independent cross-wrapper and SDK-parent refusal fixtures, cleanup authorization, budgets and
identity preservation. It uses disposable host doubles and cannot reclaim real storage or prove
an image. Mutation recipes remove the corresponding guards and must fail assertions. Existing
`test-proof-workflows.sh` remains responsible for the isolated runner and observer transport.
